# ExplainBack - Source ingestion (Block 2)

## Delivered scope

`POST /api/sources` accepts one text source or one genuine PDF/DOCX file, extracts
text, and returns a validated `ImportedSource` using the backend domain contract.
Title is optional metadata. The route uses Node.js, requires no AI API key, and
does not persist documents. No topics, graphs, summaries, or evaluations are produced.
The proposed Block 1 `/api/source/analyze` endpoint keeps its full-analysis meaning
and has not been implemented or repurposed.

Code, comments, fixtures, and documentation use English. Block 2 did not modify
UI components, CSS, `src/types/lesson.ts`, or the recorder. The merged UI has
source/explanation file inputs and microphone recording, but its provisional
evaluation/transcription clients do not call `POST /api/sources`. Its
PDF/DOC/DOCX/GDOC and 10 MB file checks differ from this API's PDF/DOCX and
3,000,000-byte limits. Coordinate these before wiring source ingestion.

## Input and limits

| Limit | Value |
| --- | --- |
| Uploaded file | 3,000,000 actual bytes |
| PDF pages | 30 physical pages |
| Original/extracted and normalized text | 100,000 UTF-16 code units each |
| Title | 200 UTF-16 code units before trimming |
| Normalized block | At most 2,000 UTF-16 code units |
| DOCX expanded archive | 10,000,000 bytes total |
| DOCX expanded entry | 5,000,000 bytes |
| DOCX entry count | 1,000 |
| Entire request body | 3,065,536 actual bytes, including multipart overhead |

All constants live in `src/backend/contracts/source-limits.ts`. Limits are enforced
on the server; violations return errors rather than truncating content. Text limits
include separators between original PDF page segments. Whitespace-only source
text is rejected. Blank titles are omitted after trimming.

### JSON text request

Content-Type: `application/json` (UTF-8).

```json
{
  "schemaVersion": "1.0",
  "source": {
    "kind": "text",
    "title": "Photosynthesis",
    "text": "Glucose stores chemical energy."
  }
}
```

This reuses Block 1's text input shape. Unknown fields, invalid versions, and
non-text JSON sources are rejected. Use multipart for file bytes rather than
JSON/base64, URLs, or local filesystem paths.

### Multipart PDF/DOCX request

Content-Type: `multipart/form-data`, with the boundary generated by the client.

- `file`: exactly one binary PDF or DOCX file.
- `title`: optional string, at most one part.

There is no JSON metadata part in this ingestion endpoint. Sending source text,
extra fields, multiple files, or duplicate titles is an invalid request.
File detection uses actual bytes followed by parsing/validation. Filename,
extension, MIME, and Content-Length alone are not trusted. A valid DOCX named
`lesson.pdf` is imported as DOCX; arbitrary bytes named `lesson.pdf` are rejected.

## Success response

HTTP 200, `Content-Type: application/json`, `Cache-Control: no-store`.
The source ID is `data.document.id`. IDs are generated once per import with UUIDs;
consumers must retain them rather than generating replacements.

This complete example uses readable IDs for documentation; actual responses use UUIDs:

```json
{
  "ok": true,
  "schemaVersion": "1.0",
  "data": {
    "schemaVersion": "1.0",
    "document": {
      "id": "source-example",
      "kind": "text",
      "blocks": [
        {
          "id": "block-example",
          "documentId": "source-example",
          "text": "Glucose stores chemical energy.",
          "location": { "paragraph": 1 },
          "original": {
            "segmentId": "segment-example",
            "charRange": { "start": 0, "end": 31 }
          },
          "normalizedRange": { "start": 0, "end": 31 }
        }
      ]
    },
    "originalSegments": [
      { "id": "segment-example", "text": "Glucose stores chemical energy." }
    ],
    "normalizedText": "Glucose stores chemical energy.",
    "metadata": {
      "extractor": "text",
      "originalCharacterCount": 31,
      "normalizedCharacterCount": 31
    },
    "warnings": []
  }
}
```

For files, metadata additionally contains `fileSizeBytes`. For PDFs, it also
contains `pageCount`, and each original segment has its physical `page` number.
DOCX has no pageCount or invented pages.

### Text versions, blocks, and evidence positions

- `originalSegments[].text` contains the exact input text for JSON, or the original
  extractor output for files. It is not the file's binary contents. Binary files
  are processed in memory and not retained by the server.
- PDF has one original segment per page, including pages with no extracted text.
  Text/DOCX has one original segment for the document's ordered extracted text.
- Normalization changes CRLF/CR into LF and trims boundary whitespace only. It
  does not paraphrase, correct formulas, remove negation, remove headers/footers,
  join hyphenated words, or classify topics.
- `normalizedText` joins normalized original segments using two newlines.
  Splitting blocks does not insert text into this value.
- Blocks follow paragraph and page boundaries. Only oversized paragraphs are split,
  preferring sentence endings, then whitespace, then a hard boundary. Hard splits
  do not break UTF-16 surrogate pairs or CRLF sequences.
- `location.paragraph` is 1-based non-empty extracted paragraph order: within the
  PDF page, or across the text/DOCX document. Multiple chunks of a long paragraph
  keep the same paragraph position. PDF blocks never span pages.
- `original.charRange` is `[start, end)` in the referenced original segment.
  Normalizing that exact slice must equal `block.text`.
- `normalizedRange` is `[start, end)` in `normalizedText`; that exact substring
  must equal `block.text`. All offsets count UTF-16 code units, not bytes.
- A later Evidence.charRange remains relative to `block.text` under Block 1.
  Ingestion ranges establish source provenance, not semantic correctness evidence.

The validator checks ordered, non-overlapping ranges, exact text matches, source/
block references, character counts, pages, and warnings before returning a result.
It detects missing non-whitespace source content. No AI meaning checks are performed.

### PDF and DOCX warnings

`EMPTY_PDF_PAGE` includes the physical page number when a page has no extractable
text while other pages do. Its empty segment remains in the result. Do not imply
that its images or missing text were read. An entirely empty/image-only PDF returns
OCR_UNSUPPORTED instead of a successful empty source.

`DOCX_EXTRACTION_WARNING` explains that text extraction preserves paragraphs and
table-cell text in document order but not table layout, images, or complex equation
formatting. Mammoth raw-text extraction provides paragraph boundaries, not stable
page numbers or table row/column coordinates. Review the original for content not
represented as plain text. Library diagnostic contents are not exposed.

## Errors

Errors use the existing `ApiResponse` envelope and non-200 status codes:

```json
{
  "ok": false,
  "schemaVersion": "1.0",
  "error": {
    "code": "OCR_UNSUPPORTED",
    "message": "PDF has no usable text layer. Scanned/image-only PDFs require OCR, which is not supported.",
    "retryable": false
  }
}
```

| HTTP | Code | Cause |
| --- | --- | --- |
| 400 | INVALID_REQUEST | Empty input, invalid JSON/UTF-8/multipart, invalid title, ambiguous input, extra/duplicate fields |
| 413 | PAYLOAD_TOO_LARGE | File, page, text, title, request, or expanded DOCX limit exceeded |
| 415 | UNSUPPORTED_SOURCE | Unsupported request media type or file bytes |
| 422 | UNREADABLE_DOCUMENT | Corrupt PDF/DOCX, unsupported ZIP, malformed Word content, or empty DOCX |
| 422 | OCR_UNSUPPORTED | PDF contains no usable extractable text |
| 422 | PASSWORD_REQUIRED | Password-protected PDF |
| 500 | SOURCE_IMPORT_FAILED | Unexpected import failure or invalid output contract |

Messages are controlled and do not include document contents, parser stacks,
or secrets. No document content is logged. Imports do not perform database ID
lookups. The API only implements POST; other methods follow Next.js route behavior.

## Run and test locally from PowerShell

Requires Node.js 22+; verified with Node 24.13.1. Open two terminals:

```powershell
Set-Location C:\code\ExplainBack
npm run dev
```

In the second terminal, send text:

```powershell
$sourceRequest = @{
  schemaVersion = "1.0"
  source = @{
    kind = "text"
    title = "Synthetic lesson"
    text = "Glucose stores chemical energy."
  }
} | ConvertTo-Json -Depth 5
$sourceResult = Invoke-RestMethod -Uri "http://localhost:3000/api/sources" `
  -Method Post -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($sourceRequest))
$sourceResult.data.document
$sourceResult.data.warnings
```

Send checked-in PDF/DOCX fixtures using `curl.exe`, which works without PowerShell
7's `-Form` option:

```powershell
curl.exe --silent --show-error --request POST "http://localhost:3000/api/sources" `
  --form "file=@C:\code\ExplainBack\tests\sources\fixtures\text.pdf;type=application/pdf" `
  --form "title=Synthetic PDF lesson"

curl.exe --silent --show-error --request POST "http://localhost:3000/api/sources" `
  --form "file=@C:\code\ExplainBack\tests\sources\fixtures\paragraphs-table.docx" `
  --form "title=Synthetic DOCX lesson"
```

Replace the file with `image-only.pdf`, `password.pdf`, or `corrupt.docx` to check
error envelopes. Add `--include` to display HTTP statuses as well as JSON.

Run contract and ingestion checks:

```powershell
node --test --test-isolation=none tests/contracts/validate.mjs
node node_modules/typescript/bin/tsc -p tests/sources/tsconfig.json
node --test --test-isolation=none tests/sources/ingest.mjs
npm run typecheck -- --incremental false
npm run build
```

The ingestion test config emits isolated test code under ignored `test-results/`;
it does not change the application config. Tests require no AI key and use only
small, synthetic documents without personal data.

For production HTTP smoke tests, after building, start another terminal:

```powershell
npm run start -- --hostname 127.0.0.1 --port 3100
```

Then run:

```powershell
node --test --test-isolation=none tests/sources/http.mjs
```

Override `SOURCE_API_BASE_URL` to test another local server. Fixture regeneration
uses `tests/sources/generate_fixtures.py` and the Python packages reportlab,
python-docx, and pypdf; these were available in the Codex bundled runtime.
They are test-fixture authoring tools, not production runtime dependencies.

## Frontend integration handoff

- Keep source text, title, and selected file while loading or after an error.
  Only replace the current source with a successful response.
- Send exactly one input. If a file is selected, do not also send source text.
  Use a FormData file part directly; let the browser set its multipart boundary.
- Client checks may mirror SOURCE_LIMITS, but server checks remain authoritative.
  JavaScript string.length matches the API's character-count convention.
- Handle loading, non-200 errors, and warnings explicitly. For PDFs with empty
  pages, show the affected page numbers; for DOCX, retain the extraction caveat.
- Retain the complete ImportedSource in session state for the future AI block.
  `document.id` alone cannot reload it from this server. Keep the block IDs and
  original/normalized ranges for future source evidence navigation.
- Do not send ImportedSource to the existing evaluation contract as though it were
  SourceAnalysis: analysis must first create its topics, graph, and lesson sections.
- No component, style, recorder behavior, or UI shared type was changed in this block.

[unpdf](https://github.com/unjs/unpdf) 1.8.1 for serverless PDF.js text extraction;
[Mammoth](https://github.com/mwilliamson/mammoth.js) 1.13.0 for DOCX raw text;

was added. unpdf requires Node 22+, recorded in package engines and README.

declared and actual inflated sizes, duplicates, and encryption before Mammoth
parses the document. No custom ZIP/XML parser or filesystem extraction is used.

the route runs and may return a platform-specific error envelope.
